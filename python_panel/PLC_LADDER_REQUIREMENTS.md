# Требования к лестничной программе (MAIN.LD) для Inovance Easy521

Что нужно добавить на ladder-диаграмме, чтобы ПЛК полностью соответствовал
тому, что софт (Python-панель и Rust/Tauri) реально пишет и читает по Modbus.

Адресный контракт ниже — **источник истины**: и `python_panel/plc_panel/config.py`
(`AXES`, `IO`), и `src_tauri/src/config.rs` приведены к этим адресам. Лестничную
программу пишут в AutoShop; этот файл — спецификация для инженера ПЛК.

Соглашение: один `REAL` = два смежных регистра, младшее слово первым
(`[low, high]`).

## 1. Что уже реализовано (ось X / `Axis_0`)

|------|------|----------|

D50 остаётся заглушкой в конфиге.

Телеметрия (D, чтение софтом):

| Сигнал | X | Y | Z |
|---|---|---|---|
| ReadActualPosition | D210 | D230 | D250 |
| ReadActualVelocity | D214 | D234 | D254 |

> накрывал блок ошибок оси X (`D220/D222`), а внутри оси пересекались REAL'ы

> Y/Z писать строго под неё.

## 3. Чек-лист блоков к добавлению

### 3.1 Оси Y и Z — полный комплект MC-блоков (главный пробел)
В MAIN.LD есть только `Axis_0`. Продублировать всю логику оси X на `Axis_1`(Y)
и `Axis_2`(Z), привязав к coil'ам и D-регистрам из §2.

- [ ] `Axis_1` (Y): MC_Power `M20`, MoveVelocity `M21`, Reset `M22`,
      MoveAbsolute `M23`, ReadAxisError `M25`, Stop `M26`, SetPosition `M27`,
      MoveRelative `M29`; ReadActualPosition → D230, ReadActualVelocity → D234.
- [ ] `Axis_2` (Z): MC_Power `M30`, MoveVelocity `M31`, Reset `M32`,
      MoveAbsolute `M33`, ReadAxisError `M35`, Stop `M36`, SetPosition `M37`,
      MoveRelative `M39`; ReadActualPosition → D250, ReadActualVelocity → D254.
- [ ] У каждой оси удерживать MC_Power (Enable), пока ось должна принимать
      движение.
- [ ] ErrorID всех MC-блоков выводить в D200 (как у X).

### 3.2 Дискретные выходы Easy521
- [ ] **Y1 — статический уровень:** рунг `M52 → Y1` (прямая катушка). Софт пишет
      `M52` (IO.Y1_TOGGLE) для постоянного уровня.
- [ ] **Y2 — генератор частоты:** инструкция аппаратного импульсного/частотного
      выхода Easy521 (`PLSF`/`PLSY`/`PWM` — по прошивке): частота берётся из
      `D90` (REAL), разрешение по `M53`, выход на `Y2`.

> Софт читает обратно `read_coils(M50..M53)` для подсветки индикаторов выходов —
> `M52` и `M53` должны быть реальными катушками, отражающими фактическое
> состояние.

### 3.3 Дискретные входы и аппаратная блокировка по концевику

> ⚠️ **Уточнение по фактическому MAIN.LD.** В текущей программе `M100` и `M101`
> заняты логикой блокировки, а **не** являются зеркалами входов:
> - `X0 → SET M100` — концевой выключатель защёлкивает блокировку;
> - `M101 → RST M100` — катушка `M101` снимает блокировку.
>
> Поэтому софт:
> - читает `M100` как признак «заблокировано» (`read_coils`), показывает его
>   индикатором «Блокировка» на рабочей вкладке;
> - по кнопке «Сброс блокировки» подаёт импульс на `M101`;
> - читает физические входы `X0/X1/X2` как **discrete inputs (FC02)**,
>   адреса `0/1/2` (см. `config.IO.LIMIT_INPUT_BASE`).

- [x] `X0 → SET M100`, `M101 → RST M100` — блокировка/снятие (есть в MAIN.LD).
- [ ] Подтвердить, что физические входы `X0/X1/X2` доступны как Modbus
      discrete inputs по адресам `0/1/2`; иначе скорректировать
      `config.IO.LIMIT_INPUT_BASE` или пробросить входы в читаемые катушки.
- [ ] Если нужны отдельные мониторы прочих входов — пробросить их в **свободные**
      катушки (не `M100/M101`), напр. `M104+`, и расширить карту в `config.IO`.

### 3.4 Безопасность — E-Stop
- [ ] По `X3`/`M103`: MC_Stop (или снятие MC_Power) на **все** оси + блокировка
      `Y0`.
- [ ] Аппаратный контур E-Stop оставить независимым от прикладной логики ПЛК.

### 3.5 Авто-импульс замера для осей Y/Z
Сеть `Done → TPR → out_pulse → Y0` сейчас завязана только на `ma_point_reached`
оси X и `M14`. Если замер триггерится по приезду любой сканирующей оси:

- [ ] Расширить условие до
      `(Axis0.Done·M14) ∨ (Axis1.Done·M24) ∨ (Axis2.Done·M34) → TPR → out_pulse → Y0`.

### 3.6 (Рекомендуется) Базирование MC_Home
Входы `X0`/`X1` названы «Home X/Home Y», но блока базирования нет — нуль сейчас
задаётся через MC_SetPosition.

- [ ] Добавить MC_Home по концевику на каждую ось **либо** явно зафиксировать
      процедуру: ручной выход на концевик + MC_SetPosition.

## 4. Приоритет

1. **Оси Y и Z** (§3.1) с непротиворечивой картой регистров §2 — без этого
   3-осевое сканирование не работает.
2. Выходы `Y1` (M52) и частотный `Y2` (M53/D90) — §3.2.
3. Входы `X0/X1/X2` + блокировка `M100`/`M101` — §3.3.
4. Реакция на E-Stop — §3.4.
5. Авто-импульс для Y/Z — §3.5.
6. Опционально MC_Home — §3.6.

После реализации Y/Z сверьте адреса с `config.py` (`AXES`) и `config.rs` — они
уже приведены к §2.
