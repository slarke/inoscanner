# REST + WebSocket API управления ПЛК (`plc_api`)

HTTP-сервис для управления сканером XYZ на **текущей** программе ПЛК
(`MAIN.LD` в корне репозитория) и текущей карте регистров
(`plc_panel/config.py`). Команды отправляются через REST, телеметрия и
события приходят потоком по WebSocket.

API не зависит от Qt и не использует GUI-панель. **Не запускайте API и панель
одновременно для управления**: оба пишут в одни и те же катушки ПЛК.

## Запуск

```bash
cd python_panel
pip install -r requirements.txt           # добавлен aiohttp

python -m plc_api --simulate              # эмулятор ладдера, без железа
python -m plc_api                         # реальный ПЛК из app_config.json
python -m plc_api --plc-ip 192.168.4.88 --port 8765 --token SECRET
```

| Аргумент | По умолчанию | Смысл |
|---|---|---|
| `--config` | `python_panel/app_config.json` | IP/порт ПЛК, `active_axes`, `arrival_tolerance_mm`, `limits`, период опроса |
| `--plc-ip`, `--plc-port` | из конфига | Переопределить адрес ПЛК |
| `--host`, `--port` | `127.0.0.1`, `8765` | Адрес HTTP-сервера |
| `--token` | env `PLC_API_TOKEN` | Bearer-токен для всех `/api/*` |
| `--simulate` | — | Эмулятор текущего ладдера (`plc_api/sim.py`) |
| `--no-soft-limits` | — | Не проверять уставки по `limits` |
| `--insecure` | — | Разрешить внешний `--host` без токена |

На внешнем адресе без токена сервер **не запустится**: API управляет
оборудованием.

## Веб-интерфейс `/docs`

Откройте `http://127.0.0.1:8765/docs` (с `/` — редирект туда же). Страница
работает без интернета: Swagger UI 5.33.0 встроен в пакет
(`plc_api/static/swagger-ui/`, лицензия Apache-2.0).

- **Пульт** (открывается по умолчанию) — по карточке на ось с живой
  позицией: питание, сброс ошибок, СТОП, «в точку» (с ожиданием приезда),
  шаг ±, движение со скоростью ◀ ▶, установка/обнуление координаты, снятие
  блокировки. Вверху — **«СТОП ВСЕ ОСИ» (клавиша Esc)**, питание всех осей,
  Y0. Ограничения ладдера видны сразу: импульс Y0 предлагается только у X,
  неподключённые оси серые, при блокировке кнопки движения выключены, у поля
  позиции показаны пределы. Результат каждой команды — в карточке и в
  журнале; введённые скорости и шаги запоминаются в браузере. «СТОП» во время
  «Ехать» сразу прерывает ожидание (ответ 409 `aborted`).
- **REST (Swagger)** — все эндпоинты со схемами, примерами и кодами ошибок;
  «Try it out» → «Execute» отправляет **реальные** команды на ПЛК. Если
  сервер запущен с токеном, введите его через «Authorize» — он запомнится в
  браузере.
- **WebSocket** — живой монитор: таблица осей (позиция, скорость, питание,
  блокировка, концевики), ошибки, журнал событий (`command`, `arrived`,
  `blocked`, `connection`), выбор событий и прореживание телеметрии на лету,
  ping. Токен берётся из поля на вкладке или из «Authorize» Swagger.

Спецификация OpenAPI 3.0 — `GET /api/v1/openapi.json`. Она открыта без
токена (секретов не содержит; Swagger загружает её до «Authorize»), остальные
`/api/*` по-прежнему требуют токен. Спецификация собирается в
`plc_api/openapi.py` из тех же констант ладдера; тест
`tests/test_api_docs.py` проверяет, что она описывает ровно те маршруты,
что есть у сервера.

## Модель работы

- Все обращения к ПЛК выполняет один поток `plc-io`, который владеет
  Modbus-соединением. HTTP-запросы ставят команды в очередь; стоп и
  «стоп всех осей» идут с приоритетом и обгоняют ожидающие команды.
- Ответ `202 {"status": "sent"}` означает, что **регистры и строб записаны**,
  а не что движение выполнено. Приезд определяется по телеметрии: запрос
  `move-absolute` с `"wait": true` или событие `arrived` в WebSocket.
- Связь восстанавливается автоматически (пауза 2 с). Команды, ожидавшие в
  очереди в момент обрыва, отклоняются с кодом 503, а не выполняются позже.
- Проверки **до** отправки на ПЛК: ось существует и подключена
  (`active_axes`), не заблокирована концевиком, уставка в пределах `limits`,
  функция реализована текущим ладдером.

## Аутентификация

При заданном токене каждый запрос к `/api/*` должен содержать
`Authorization: Bearer <token>`. WebSocket из браузера может передать токен
параметром `?token=<token>`.

## Ошибки

Любая ошибка возвращается как `{"error": {"code": "...", "message": "..."}}`.

| HTTP | code | Когда |
|---|---|---|
| 400 | `bad_request` | Не JSON, неизвестное поле, неверный тип, недопустимое значение |
| 401 | `unauthorized` | Нет или неверный токен |
| 404 | `not_found` | Неизвестная ось или путь |
| 409 | `conflict` | Ось заблокирована концевиком или не подключена; блокировка во время ожидания приезда |
| 409 | `aborted` | Ожидание приезда (`wait`) прервано стопом, новой командой этой оси или снятием питания |
| 422 | `out_of_limits` | Уставка вне `limits` |
| 422 | `unsupported_by_ladder` | Текущий `MAIN.LD` это не реализует (импульс по Y/Z) |
| 502 | `plc_io_error` | ПЛК отклонил запрос или обмен сорвался |
| 503 | `plc_not_connected` | Нет связи с ПЛК |
| 504 | `timeout` | Команда не выполнена за 5 с или ось не приехала за `timeout_s` |

Тело проверяется строго: опечатка в имени поля (`"postion"`) даёт 400, а не
молча игнорируется.

## Эндпоинты

Ось в пути: `x|y|z` или `1|2|3`.

### Состояние

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/v1/health` | `connected`, `detail`, `telemetry_age_s`, `pending_commands`, `version` |
| GET | `/api/v1/capabilities` | Адреса регистров по осям, что поддерживает ладдер, ограничения, `active_axes`, `soft_limits` |
| GET | `/api/v1/telemetry` | Последний кадр опроса (формат ниже) |
| GET | `/api/v1/axes/{axis}` | Часть кадра по одной оси |

### Команды осей

| Метод | Путь | Тело | Регистры (X / Y / Z) |
|---|---|---|---|
| POST | `/axes/{axis}/power` | `{"on": bool}` | M10 / M20 / M30 (уровень) |
| POST | `/axes/{axis}/reset` | — | строб M12 / M22 / M32, 100 мс |
| POST | `/axes/{axis}/move-absolute` | `{"position", "speed", "pulse"=false, "wait"=false, "timeout_s"=60}` | D16,D18 / D106,D108 / D136,D138 + строб M13 / M23 / M33; `pulse` → M14 (только X) |
| POST | `/axes/{axis}/move-relative` | `{"distance", "speed"}` | D20,D22 / D110,D112 / D140,D142 + строб M19 / M29 / M39 |
| POST | `/axes/{axis}/move-velocity` | `{"speed", "acceleration", "deceleration"}` | D10–D14 / D100–D104 / D130–D134 + строб M11 / M21 / M31 |
| POST | `/axes/{axis}/stop` | — | строб M16 / M26 / M36 (приоритетно) |
| POST | `/axes/{axis}/set-position` | `{"position"}` | D24 / D114 / D144 + строб M17 / M27 / M37 |
| POST | `/axes/{axis}/unblock` | — | строб M101 / M201 / M301, 100 мс |

Все пути выше начинаются с `/api/v1`. Позиции в мм; REAL — float32,
младшее слово первым.

### Общие команды

| Метод | Путь | Тело | Действие |
|---|---|---|---|
| POST | `/api/v1/stop-all` | `{"power_off"=false}` | MC_Stop на всех осях одновременно; опционально снять MC_Power |
| POST | `/api/v1/io/y0/pulse` | — | строб M50 (SET Y0) → 150 мс → строб M51 (RST Y0) |
| PUT | `/api/v1/io/y0` | `{"high": bool}` | HIGH: удерживать M50. LOW: отпустить M50 и дать *строб* M51 |

`stop-all` — программный стоп через Modbus; аппаратный аварийный стоп он
не заменяет.

Про LOW на Y0: панель удерживает M51, и тогда `RST Y0` на каждом скане
глушит авто-импульсы замера. API даёт на M51 только строб.

### Примеры

```bash
curl -X POST localhost:8765/api/v1/axes/x/power -d '{"on": true}'
curl -X POST localhost:8765/api/v1/axes/x/move-absolute \
     -d '{"position": 120.5, "speed": 20, "pulse": true, "wait": true, "timeout_s": 30}'
curl -X POST localhost:8765/api/v1/stop-all -d '{"power_off": true}'
```

## Формат телеметрии

```json
{
  "timestamp": 1790000000.12,
  "axes": {
    "X": {"axis": 1, "active": true, "position": 120.5, "velocity": 0.0,
          "power_command": true, "blocked": false,
          "limit_left": false, "limit_right": false}
  },
  "errors": {"block_error_id": 0, "servo_error_id": 0, "axis_error_id": 0,
             "shared_between_axes": true},
  "y0": {"set_command": false, "reset_command": false}
}
```

`null` означает, что значение не удалось прочитать. Честные оговорки о
текущем ладдере:

- `power_command` — это команда M10/M20/M30, а не фактический статус
  привода (выход `Status` MC_Power в ладдере никуда не выведен);
- `errors` — общий блок D220/D222 для всех трёх осей: значение принадлежит
  оси, чей блок выполнился последним; D200 — общий ErrorID MC-блоков;
- `limit_left`/`limit_right` читаются как discrete inputs 1…6; соответствие
  этих адресов входам X1…X6 на Easy521 не подтверждено;
- `y0` — состояние *команд* M50/M51, а не физического выхода Y0.

## WebSocket `/api/v1/ws`

Сервер сам присылает события; команды через WebSocket не принимаются, только
через REST.

Параметры подключения (необязательные):
`?events=telemetry,arrived` — фильтр событий;
`?telemetry_interval_ms=500` — прореживание телеметрии (по умолчанию каждый
кадр опроса, `poll_interval_ms` из конфига).

**Сервер → клиент**

| type | Поля | Когда |
|---|---|---|
| `hello` | `version`, `status`, `events`, `telemetry` | Сразу после подключения |
| `telemetry` | `data` (формат выше) | Каждый кадр опроса |
| `connection` | `connected`, `detail` | Связь с ПЛК появилась или пропала |
| `command` | `command`, `axis`, `params` | Команда записана в ПЛК (от любого клиента) |
| `arrived` | `axis`, `target`, `position` | Ось пришла в уставку `move-absolute`/`move-relative` |
| `blocked` | `axis`, `blocked` | Изменилась защёлка блокировки по концевику |

**Клиент → сервер**

| Сообщение | Ответ |
|---|---|
| `{"type": "ping"}` | `{"type": "pong"}` |
| `{"type": "subscribe", "events": [...], "telemetry_interval_ms": 200}` | `{"type": "subscribed", ...}` |

Медленный клиент теряет устаревшие кадры телеметрии, но не события
`connection`, `arrived` и `blocked`.

```js
const ws = new WebSocket("ws://127.0.0.1:8765/api/v1/ws?events=telemetry,arrived&telemetry_interval_ms=200");
ws.onmessage = (m) => console.log(JSON.parse(m.data));
```

## Что текущий ладдер не позволяет (и API не обещает)

- импульс замера по приезду на Y и Z (`pulse: true` → 422);
- замедление MC_Stop из API (задаётся переменными ПЛК);
- выходы Y1 (M52) и Y2 (M53/D90);
- аппаратный E-stop и handshake-регистры D400+ (варианта B нет).

После доработки `MAIN.LD` правится `plc_api/ladder.py`, а не сервер или
контроллер.

## Код и тесты

| Модуль | Назначение |
|---|---|
| `plc_api/ladder.py` | Контракт текущего MAIN.LD: что поддерживается, тайминги стробов |

| `plc_api/openapi.py` | Спецификация OpenAPI 3.0 |
| `plc_api/static/` | Страница `/docs`: `docs.html/css`, `docs.js` (вкладки, Swagger, монитор WS), `control.js` (пульт), встроенный Swagger UI |

`tests/test_api_docs.py`
(`python -m pytest` из корня; без железа и без сети наружу).
