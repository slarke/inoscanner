# CLAUDE.md

Контекст для агента, работающего с этим репозиторием. Прочитай целиком перед
любыми правками: здесь зафиксированы решения, которые легко сломать по незнанию.

## Что это

`servo_core` — ядро надёжной очереди команд для цепочки
**PyQt → очередь → Modbus → ПЛК → сервопривод**.

Роли строго разделены: **ПЛК** исполняет реальное движение (real-time, разгон/
торможение, безопасность). **Python** — супервайзер: надёжно ставит команды в
очередь, ведёт handshake с ПЛК, обеспечивает отсутствие потери команд и
отсутствие двойного запуска движения после сбоев питания, крашей и обрывов связи.

Python НЕ является real-time слоем. Любая логика, зависящая от детерминированного
тайминга, относится к ПЛК, а не сюда.

## Команды

```bash
python -m servo_core.demo          # headless: штатный путь + краш/recovery, без железа и Qt
pip install PyQt6 pymodbus
python -m servo_core.pyqt_example   # GUI-пример (нужен PyQt6)
python -m compileall servo_core     # быстрая проверка синтаксиса
```

`demo.py` — исполняемая проверка инвариантов (в т.ч. идемпотентности после
краша). После любой правки ядра он должен проходить и заканчиваться строкой про
effectively-once. Если сломался — сломана корректность, а не «тест».

## Архитектура и правило зависимостей

| Слой | Файл | Ответственность |
|---|---|---|
| БД | `database.py` | одна SQLite, WAL, транзакции, миграции |
| DAO | `repository.py` | очередь + история + dead-letter + seq, транзакционно |
| транспорт | `driver.py` | Modbus ABC + pymodbus; **без бизнес-логики** |
| протокол | `protocol.py` | команда/seq ↔ регистры по `RegisterMap` |
| оркестрация | `executor.py` | handshake-автомат, retry, recovery |
| watchdog | `watchdog.py` | двунаправленный контроль связи, свой поток |
| супервайзер | `supervisor.py` | поток на канал, изоляция, авто-перезапуск, E-stop-гейт |
| фасад | `service.py` | API для GUI, backpressure |
| события | `events.py` | Qt-агностичная шина |
| Qt-мост | `qt_bridge.py` | EventBus → pyqtSignal, импорт PyQt защищён |
| мок | `mock.py` | модель ПЛК + mock-драйвер для запуска без железа |

**Правило зависимостей — внутрь.** `executor` зависит от абстракций
`ModbusDriver` и `CommandRepository`, не от реализаций. Не вводи прямые
зависимости от pymodbus или PyQt в ядре. Это то, что позволяет тестировать
без железа (mock) и без Qt (EventBus напрямую). Ядро обязано импортироваться
headless — проверяй `import servo_core` без установленного PyQt6.

## Инварианты, которые НЕЛЬЗЯ нарушать

1. **Транзакционная связность.** Снятие команды с очереди и запись в
   `command_history`/`dead_letter` — всегда одна транзакция (`Database.transaction`).
   Никогда не делай `ack`/`delete` очереди и запись истории отдельными операциями.
   Именно ради этого выбрана своя SQLite, а НЕ persist-queue. Не возвращай
   persist-queue.

2. **`ack` очереди — по факту отработки ПЛК.** Команда закрывается только при
   `ack_seq == seq && state == DONE`, а не после успешной записи в шину. Успешный
   `write_registers` означает лишь «байты ушли», не «движение выполнено».

3. **Идемпотентность через seq.** Команда блока пишется одним FC16, `seq`
   логически последний (`protocol.encode_command`). Дедуп — на ПЛК по
   `last_processed_seq`. Доставка at-least-once, исполнение at-most-once =
   effectively-once. Не называй это exactly-once.

4. **Только абсолютные команды.** `MotionCommand.target_position` абсолютна.
   Не добавляй относительных перемещений: их повтор после краша накапливает
   смещение и ломает идемпотентность.

5. **Recovery гейтится E-stop.** При старте, если ПЛК в E-stop/guard_open,
   движение НЕ возобновляется автоматически — нужен `acknowledge_safe_state()`
   от оператора. Не делай безусловный resume.

6. **E-stop вне очереди.** Аварийный стоп не проходит через FIFO. Не добавляй
   «команду стоп» в очередь как штатную.

7. **monotonic seq на канал, в БД.** Не сбрасывай seq при старте, не используй
   uuid вместо seq (нужен порядок для дедупа).

8. **Один Modbus-клиент на канал, не шарится между потоками.** Синхронный клиент
   pymodbus не потокобезопасен. Поток на канал владеет своим драйвером.

9. **Изоляция каналов.** Ошибка на одном порту не должна валить другие.
   `ChannelWorker._run` ловит всё и перезапускает только свой канал.

## Конвенции кода

- Идентификаторы — английские; docstring/комментарии — русские (аудитория проекта).
- Везде type hints, `from __future__ import annotations`.
- `driver.py` — только чтение/запись регистров, никакой логики команд/seq/состояний.
- Dataclasses для моделей, Enum для состояний. `MotionCommand` и `QueuedCommand`
  фрозены.
- Подписчик EventBus не должен ронять ядро (исключения подавляются в `publish`).

## Ответственность ПЛК (вне этого кода, но система от этого зависит)

Эти вещи реализуются на ПЛК; Python их использует, но заменить не может. Если их
нет — гарантии не держатся:

- Дедуп: при `seq <= last_processed_seq` движение не запускать, вернуть
  `ack_seq = seq, state = DONE`.
- Запуск только при `req_seq != ack_seq && ready`; payload защёлкивать атомарно.
- Dead-man: если watchdog-регистр от Python застыл — перевести привод в безопасное
  состояние.
- Аппаратный E-stop, независимый от Python и от прикладной логики ПЛК.

## Карта регистров (текущая, заглушечная)

`RegisterMap` в `config.py` — адреса под конкретный привод. Текущие значения
условные. Блок команды: `[target_hi, target_lo, speed, command_code, seq_hi,
seq_lo]`. Блок статуса: `[ack_seq_hi, ack_seq_lo, command_state, error_code,
status_flags]`. Кодировка `command_state` — в `models.PLC_STATE_BY_CODE`.

## Известные ограничения / на что смотреть

- **pymodbus**: имя kwarg адреса устройства зависит от версии
  (`unit` → `slave` → `device_id`). В `driver.py` стоит `device_id` под 3.13.x —
  единственное место правки. Версию пинить в requirements.
- **mock.py** — упрощённая модель ПЛК для проверки логики ядра, не эталон
  реального привода. Реальный профиль регистров и тайминги будут другими.
- Тесты на краш-сценарии (kill в середине транзакции + проверка целостности БД)
  ещё не написаны — это следующий логичный шаг.
- Миграции схемы: при изменении таблиц поднимай `SCHEMA_VERSION` и добавляй шаг
  в `Database._migrate`. Не меняй существующие таблицы без миграции.

## Чего не делать

- Не тащить брокеры (Redis/RabbitMQ/Celery/Kafka) — это standalone-приложение на
  Windows, брокер = лишняя точка отказа.
- Не делать Modbus-I/O в GUI-потоке.
- Не превращать `driver.py` в место для бизнес-логики.
- Не «оптимизировать» транзакции, разделяя очередь и историю.
